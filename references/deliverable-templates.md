# 交付物模板

各阶段产出的标准结构,生成时直接套用,保证不同执行/不同 agent 产出一致。

## 题目解析.md(Stage 1 产出)

```markdown
# <比赛名> 题目解析

## 主题
<一句话:题目要做什么>

## 约束
- 时间 / 模型 / 技术栈 / 规模 / 团队 等硬约束

## 评审标准(驱动 PPT 重点)
- 客观指标:<完成率/耗时/Token/代码量 等>
- 主观 / 答辩:<模糊澄清/多模块拆解/反模式 等>

## 交付物
<比赛要什么:可演示系统 / PPT / 文档 / 海报 / ...>

## 格式与截止
<答辩形式 / 提交格式 / 截止时间>

## 数据源待补
- [ ] <拿不准、需用户确认或补 URL 的>
```

## idea.md(Stage 2 产出,选定 idea)

```markdown
# idea:<一句话主张>

## 问题切入
<解决的真实问题,别造>

## 解决思路
<怎么做,核心机制>

## 差异化
<为什么不被轻易复制 / 不被模型进步吞掉>

## 可行性
<给定周期(如 3 周)能不能做出来,依据>

## 评审契合
<对 rubric 各项的覆盖>

## 待确认
- [ ] ...
```

> Stage 2 先生成 1-3 个候选(用上面结构各写一份摘要 + 一张对比表),用户选定后再展开成完整的 idea.md。

## 计划.md(Stage 3 产出)

```markdown
# 计划:<项目名>

## 产品定位
<一句话 + 目标用户>

## 核心功能
1. ...
2. ...

## 架构
<文字描述 + 引用 architecture/xxx.svg>

## 里程碑
| 阶段 | 时间 | 产出 |

## 分工
| 成员 | 职责 |

## 风险
- <风险> → <缓解>
```

## PRD.md(Stage 3 产出,功能规格——给开发/评委看"做什么、怎么验")

> 和 `计划.md` 互补:计划.md 是**产品规划**(定位/架构/里程碑/分工),PRD.md 是**功能规格**(每个功能做什么、验收标准)。已有项目时,功能清单从 repo 真实能力拉,不发明。

```markdown
# PRD:<项目名>

## 背景与问题
<真实问题,从题目约束 + 项目 README 拉,别造>

## 目标
- 业务目标:<可衡量,如"3 周内可演示核心闭环">
- 用户目标:<目标用户要达成什么>

## 用户与场景
| 角色 | 典型场景 | 当前痛点 |
|---|---|---|

## 功能清单
### F1 <功能名>
- 描述:<做什么>
- 输入/输出:
- **验收标准(评委 demo 用)**:
  - [ ] <可观察的通过条件>
### F2 <功能名>
- ...

## 非目标(Out of Scope)
<明确不做的,守住边界——评委也看这个判断取舍>

## 评审契合(对 rubric 各项)
<每个功能 / 指标 → 对应评审标准哪一项,覆盖 N/M>

## 待确认
- [ ] ...
```

## 飞书产品说明书(Stage 5 产出,评委视角)

建议结构(按比赛裁剪,评委视角;发布命令见 [feishu-publish.md](feishu-publish.md)):

1. 一句话定位
2. 行业痛点 / 问题
3. 产品与功能系统
4. 架构(嵌 SVG)
5. 亮点 / 差异化
6. 数据 / benchmark(真实,从 README 拉)
7. roadmap / 后续

> 风格:去 AI 腔、书面正式、不堆网络用语。数据不准就标"待补",不发明。

## 架构 SVG(Stage 5 产出)

- 放 `architecture/` 目录
- **必须过 `whiteboard-cli --check` 0 错**才用
- 数量按项目复杂度,不硬编码张数
